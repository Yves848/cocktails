## 19:20 — Réalisé : mot de passe administrateur (sudo) demandé dans l'interface

**Demande :** intercepter le moment où `brew` réclame le mot de passe root et permettre à
l'utilisateur de le saisir depuis Cocktails, au lieu de l'échec `sudo: a terminal is
required to read the password`.

**Actions :**
- Mécanisme choisi : `SUDO_ASKPASS` (vérifié dans `system_command.rb:298` — Homebrew ajoute
  `-A` à ses appels sudo dès que la variable est définie). On n'intercepte donc plus un
  échec : on l'empêche.
- Nouveau `AskpassBroker` (Core) : écrit un script helper 0700 dans le dossier de données,
  écoute une socket UNIX 0600, et sert le mot de passe demande par demande. Le secret ne
  passe ni par la ligne de commande, ni par l'environnement, ni par un fichier.
- Rétention en mémoire seule : case « Retenir pour cette session », péremption glissante
  (60 min par défaut, réglable : 15 min / 1 h / 4 h / toute la session), minuteur de purge,
  et bouton « Oublier le mot de passe » dans Réglages. Jamais de disque, jamais de Keychain.
- Détection du mot de passe refusé : une 2ᵉ demande dans la même opération signifie que sudo
  a rejeté la précédente → cache jeté et dialogue « mot de passe incorrect ».
- `IProcessRunner` accepte des variables d'environnement ; `HomebrewService` exporte
  `SUDO_ASKPASS` sur les commandes mutantes et le terminal, pas sur les lectures.
- Dialogue modal dans le shell (↩ valide, ⎋ annule, focus automatique), fenêtre démasquée si
  l'app était réduite à la barre de menu. Chaînes localisées EN/FR/ES/DE.
- Repli si `nc` est indisponible : rien n'est exporté (comportement d'avant) et `SudoOutput`
  reconnaît les messages de sudo pour expliquer la panne dans le journal.

**Fichiers :**
- `src/Cocktails.Core/Sudo/{AskpassBroker,ISudoAskpass,SudoOutput}.cs` — nouveaux
- `src/Cocktails.Core/Process/{IProcessRunner,ProcessRunner}.cs` — paramètre `environment`

- `src/Cocktails/{App.axaml.cs,Services/SettingsStore.cs,Localization/Strings.cs}` — composition, persistance, i18n
