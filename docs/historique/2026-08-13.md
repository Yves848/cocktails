## 19:20 — Réalisé : mot de passe administrateur (sudo) demandé dans l'interface

**Demande :** intercepter le moment où `brew` réclame le mot de passe root et permettre à
l'utilisateur de le saisir depuis Cocktails, au lieu de l'échec `sudo: a terminal is
required to read the password`.

**Actions :**
- Mécanisme choisi : `SUDO_ASKPASS` (vérifié dans `system_command.rb:298` — Homebrew ajoute
  `-A` à ses appels sudo dès que la variable est définie). On n'intercepte donc plus un
  échec : on l'empêche.
- Nouveau `AskpassBroker` (Core) : écrit un script helper 0700 dans le dossier de données,
  écoute une socket UNIX 0600, et sert le mot de passe demande par demande. Le secret ne
  passe ni par la ligne de commande, ni par l'environnement, ni par un fichier.
- Rétention en mémoire seule : case « Retenir pour cette session », péremption glissante
  (60 min par défaut, réglable : 15 min / 1 h / 4 h / toute la session), minuteur de purge,
  et bouton « Oublier le mot de passe » dans Réglages. Jamais de disque, jamais de Keychain.
- Détection du mot de passe refusé : une 2ᵉ demande dans la même opération signifie que sudo
  a rejeté la précédente → cache jeté et dialogue « mot de passe incorrect ».
- `IProcessRunner` accepte des variables d'environnement ; `HomebrewService` exporte
  `SUDO_ASKPASS` sur les commandes mutantes et le terminal, pas sur les lectures.
- Dialogue modal dans le shell (↩ valide, ⎋ annule, focus automatique), fenêtre démasquée si
  l'app était réduite à la barre de menu. Chaînes localisées EN/FR/ES/DE.
- Repli si `nc` est indisponible : rien n'est exporté (comportement d'avant) et `SudoOutput`
  reconnaît les messages de sudo pour expliquer la panne dans le journal.

**Fichiers :**
- `src/Cocktails.Core/Sudo/{AskpassBroker,ISudoAskpass,SudoOutput}.cs` — nouveaux
- `src/Cocktails.Core/Process/{IProcessRunner,ProcessRunner}.cs` — paramètre `environment`
- `src/Cocktails.Core/HomebrewService.cs` — `SudoEnvironment()` + `mayUseSudo`
- `src/Cocktails/ViewModels/{PasswordRequest,MainViewModel,SettingsViewModel,AppSettings,ScreenViewModel}.cs`
- `src/Cocktails/Views/{MainWindow.axaml(.cs),SettingsView.axaml}` — dialogue + réglages
- `src/Cocktails/{App.axaml.cs,Services/SettingsStore.cs,Localization/Strings.cs}` — composition, persistance, i18n
- `tests/Cocktails.Core.Tests/{AskpassBrokerTests,HomebrewSudoTests,PasswordPromptTests,SudoOutputTests}.cs`

**Décisions / notes :**
- Développé en TDD ; 136 tests verts, build sans warning. Les tests du courtier exécutent
  réellement le script helper généré — c'est le contrat que sudo consomme.
- Vérifié contre le **vrai `sudo -A`** (sonde temporaire, non commitée) : mot de passe bien
  transmis (3 tentatives sur mot de passe faux), et **annulation → un seul appel**, sudo
  abandonne immédiatement au lieu de boucler.
- Piège corrigé au passage : `nc -U … < /dev/null` faisait sortir le relais avant lecture
  (les tests passaient par une course) → `nc -U -d`.
- Écarté : `sudo -S`, le trousseau macOS, toute persistance disque du secret.

## 22:07 — Réalisé : jigger 0.1.3 réellement installé (tag manquant)

**Demande :** `jigger` restait en 0.1.2 malgré le travail sur le sélecteur.

**Cause racine :** le code 0.1.3 était poussé sur `main` (`981e910`), mais **aucun tag
`v0.1.3`** n'existait. La formule du tap pointait donc encore sur l'archive `v0.1.2`, et
comme elle compile depuis l'archive avec `-X main.version=#{version}`, brew reconstruisait
fidèlement 0.1.2 — binaire *et* plugin zsh de `pkgshare`.

**Actions :**
- Tag annoté `v0.1.3` créé sur `981e910` et poussé sur GitLab.
- sha256 de `jigger-v0.1.3.tar.gz` calculé sur l'archive GitLab.
- Formule du tap mise à jour (url + sha256), commitée et poussée.
- `brew upgrade jigger` → `0.1.2 -> 0.1.3` ; vérifié `jigger --version` = 0.1.3 et
  plugin zsh installé identique à `shell/jigger.plugin.zsh` du dépôt.

**Fichiers :**
- `~/git/homebrew-cocktails/Formula/jigger.rb` — url `v0.1.3` + nouveau sha256.

**Décisions / notes :** penser à **taguer** jigger à chaque bump de `main.go`, sinon le tap
reste figé sur la version précédente. Le widget zsh déjà chargé dans un shell ouvert vient
de l'ancienne installation : ouvrir un nouveau shell pour voir le sélecteur 0.1.3.

**Commits :** `1edef58` (tap) jigger 0.1.3 ; tag `v0.1.3` sur `yves/jigger`.
