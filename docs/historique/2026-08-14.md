## 19:51 — Réalisé : jigger 0.4.3, le compteur du bloc oh-my-posh suit les commandes brew

**Demande :** le nombre de mises à jour du segment oh-my-posh restait faux après un
`brew upgrade`.

**Actions :**
- Cause racine mesurée : le cache `~/Library/Caches/jigger/status` n'était rafraîchi que
  par péremption de `JIGGER_PROMPT_TTL` (30 min). Cache `6.0.17 10 1` à 18:12 contre un
  `brew outdated` réel à 0/0.
- Deuxième cause, trouvée en route : le `precmd` de jigger était enregistré **après**
  celui d'oh-my-posh (ordre des `source` dans `~/.zshrc`), donc ses exports arrivaient
  une fois le prompt déjà calculé — un coup de retard quoi qu'il arrive.
- Hook `preexec` qui repère les commandes brew mutantes ; rafraîchissement synchrone dans
  le `precmd` (choix de l'utilisateur : prompt juste tout de suite plutôt que zéro
  attente) ; `jigger prompt --refresh --wait` côté Go pour ne pas se faire avaler par le
  verrou d'un rafraîchissement parti pendant l'upgrade.
- Tests : deux tests Go sur le verrou d'attente, cinq assertions zpty sur le bloc prompt.
  Passées contre le plugin d'avant : 4 échecs, dont le symptôme d'origine.
- Publication : MR !5, issue #7, tag `v0.4.3`, release GitLab, bump de la formule du tap,
  `brew upgrade jigger`.

**Fichiers :**
- `~/git/jigger/shell/jigger.plugin.zsh` — `preexec`, détection `brew <mutant>`,
  rafraîchissement forcé, `precmd_functions` réordonné, réglage `JIGGER_PROMPT_SYNC`
- `~/git/jigger/internal/prompt/status.go` — `lockWait`, `RefreshWait(With)`
- `~/git/jigger/main.go` — drapeau `--wait`, version 0.4.3
- `~/git/jigger/tests/zpty.zsh` — harnais du bloc prompt ; deux pièges corrigés
  (environnement `JIGGER_BREW_*` hérité, `haystack` non quoté dans `check`)
- `homebrew-cocktails/Formula/jigger.rb` — v0.4.3

**Décisions / notes :**
